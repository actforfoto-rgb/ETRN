# ЭТрН — Госключ · R2 FIX1

Диагностический Android-пилот для двух ЭТрН водителя-ИП. Это не готовая система массового подписания.

## Исправление

Живой R2 дошёл до подготовки и получил `Неполная информация о сертификате`: отсутствовали `Сертификат.ФИО` и `Сертификат.ИНН`. R2 не проверяла полноту выбранного объекта. Сам исходный ответ чтения документа у разработчика отсутствует; точное расположение пропущенных значений на учётке не установлено.

FIX1 собирает предложения реквизитов из профиля текущего пользователя, `НашаОрганизация.СвФЛ`, сертификатов выбранного действия и списка сертификатов документа. Обрабатываются объект и массив. Чужая сторона, произвольный вложенный ИНН и первый случайный сертификат не используются. Реквизиты для двух документов должны согласовываться.

Перед подготовкой пользователь проверяет ФИО, ИНН, ОГРНИП и статус подписанта. Недостающие данные можно дописать **по собственным документам ИП/сертификату Госключа**. Автоматическое получение всех реквизитов не гарантируется. Форма — это подтверждение реквизитов для генерации титулов, не подтверждение действительности сертификата и не новое оформление ЭП. Проверка числовых полей проверяет длину/цифры, но не принадлежность номера и не реестр ФНС.

Пустые обязательные поля и выявленные расхождения с профилем/нашей стороной блокируют PREPARE локально. Повтор той же подготовки в текущем запуске блокируется. В обоих запросах передаётся один подтверждённый набор реквизитов; отпечаток неизвестного ключа не подставляется. Этот способ передачи реквизитов предусмотрен документацией `СБИС.ПодготовитьДействие`.

## Границы пилота

- Авторизация и исходный маршрут списка/чтения/подготовки сохранены; список по-прежнему ограничен первой страницей из 50 событий и явно сообщает о наличии продолжения.
- Подписание требует отдельного согласия перед одним `sabyCryptoOperation.Create`. После попытки Create повторная отправка блокируется и при перезапуске. После тайм-аута не переустанавливать приложение ради повторной отправки: сначала проверить Госключ/статус.
- `OperationID` сам по себе не доказывает, что Госключ получил/подписал оба документа. Ошибка Create сама по себе не доказывает невозможность пакетного маршрута.
- `СБИС.ВыполнитьДействие` не вызывается. Подготовка может создать/перегенерировать ответные титулы; отсутствие финализации не означает полного отсутствия изменений на сервере.
- Лог передаётся как раньше: «Скопировать лог» → Telegram → вставить → отправить. Пароли, коды, сессии, реквизиты, ссылки и двоичные данные скрываются. Полный сырой ответ не экспортируется.
- Синтетические unit-тесты и сборка не заменяют проверку на телефоне и настоящем аккаунте. Живой FIX1 ещё не подтверждён.

## Сборка

JDK 17, Gradle 8.9, Android SDK 35. Команда: `gradle --no-daemon :app:testDebugUnitTest :app:assembleDebug`.

Одноразовая миграция `tools/apply_r2_fix1.py` применяет фикс только к известному git-blob R2. CI сохраняет полученный Java-код в репозитории после успешной сборки и тестов. Повторная миграция идемпотентна. Тесты содержат только синтетические данные. APK подписывается тестовым Android-ключом; обновление поверх APK другого CI-запуска может потребовать удаления **только нашего старого приложения**, но не Saby и не Госключа.
